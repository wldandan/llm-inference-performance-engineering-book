## 学完交付什么

完整实践交付一套可复现的模型服务，包含架构与资源选择、部署配置、运行手册、可信基线、瓶颈证据、优化对照、质量与成本检查和回归标准。已有服务的学员可从测量与诊断切入，系统知识按需补齐。

**完整训练不是必修前置。** 复杂多机、MoE、P/D分离和Kernel优化按需进阶。仅有API权限时可完成客户端与应用层测量，但不能据此宣称完成模型部署、故障恢复、服务端或GPU诊断；完整系统实践仍需可访问的后端环境。

应用方向可从 Agent 与 AI 软件工程衔接，也可直接进入本课程。三天集中实训选择单机服务、资源估算、可信测量、诊断与回归的核心路线，不替代30章教材和本仓性能专项实验的全部深度；模拟耗时不能作为真实服务性能基线。

## 教材主干：LLM 推理性能工程

以下保留现有教材介绍和进度口径；章节正文、代码、图件和已有写作改动未因目录合并而重写。

你把一个 LLM 服务跑起来了，用户说它慢。你打开监控，看到 P99 确实在涨。然后呢？

这本书讲的就是“然后呢”。它不是推理框架的使用手册，也不是优化技巧清单，而是一套能反复使用的工作方法：**怎样把“感觉慢”变成可以调查的问题，怎样拿到足以支撑结论的证据，怎样验证一次优化是真的有效还是只是噪声。**

## 这本书给谁看

- **后端工程师 / AI 应用工程师**：服务是你部署的，出了性能问题要你查。
- **Agent 工程师**：一次任务背后有多次 LLM 调用，延迟和成本都在放大，你需要知道放大在哪。
- **MLOps / 平台工程师**：你要为一群应用团队规划容量、定 SLO、守住上线质量。

**需要你已经会的**：读基础 Python、JSON 和命令行输出；理解 HTTP 请求和基本并发；看得懂折线图和分位数。

**不需要预先掌握的**：CUDA、GPU 微架构、分布式训练、Transformer 的数学推导。这些在需要时会用够用的篇幅讲清楚，深入部分放在附录。

## 你会学到什么

读完之后，面对一个真实的推理服务，你应该能做到：

| 能力 | 具体是指 |
|---|---|
| **说清楚问题** | 把“服务慢”补成现象、范围、时间、对照四项，让它变成可以调查的东西 |
| **建立可信基线** | 跑出一份别人照着能重现的 Baseline，并知道它能识别多大的改善 |
| **找到那条请求** | 从一条告警下钻到具体的慢请求，而不是在聚合指标里猜 |
| **选对工具** | 知道一个现象该用哪一层的 profiling，以及上一层为什么不够 |
| **给出可证伪的结论** | 产出一份带排除项和残留不确定性的根因报告 |
| **验证优化收益** | 用同一份负载重跑，区分真实改善和实验噪声 |

贯穿全书有一条纪律：**没有证据就写没有证据**。缺失的阶段记为 `unavailable` 而不是 `0`，客户端观测不能直接当服务端事实，单次调用不能推出性能结论。这条纪律比任何具体的优化技巧都更值得带走。

## 全书结构

七个部分，三十章，围绕同一套真实服务逐层展开：

```text
运行  →  测量  →  诊断  →  优化  →  验证  →  上线守护
```

| Part | 主题 | 章节 | 读完能交付什么 |
|---|---|---|---|
| **1** | 从一个请求理解推理系统 | Ch1–5 | 一次真实调用的完整记录与统一的指标口径 |
| **2** | 测量、观测与根因分析 | Ch6–10 | 一份可复现的 Baseline 和一份根因报告 |
| **3** | Prefill 与上下文优化 | Ch11–14 | 长 Prompt 场景下的 TTFT 优化与同流量验证 |
| **4** | Decode、KV Cache 与生成优化 | Ch15–19 | TPOT、显存与质量的联合权衡结论 |
| **5** | Serving、RAG 与 Agent 性能工程 | Ch20–25 | 一条真实应用链路的关键路径优化 |
| **6** | 容量、成本与生产工程 | Ch26–29 | 容量模型、回归门禁与上线检查清单 |
| **7** | 综合项目 | Ch30 | 一套可运行、可观测、可解释的完整服务 |

每章的结构是固定的：章首给三个问题，正文逐一展开，章末回到这三个问题逐条作答，最后附一份可以打勾的自查清单。

GPU 架构与 Roofline、CUDA 与 Kernel Profiling、多 GPU、MoE、PD Disaggregation 放在附录，不占主线篇幅。

## 覆盖范围

**讲**：纯文本 Decoder-only 模型的在线推理，涵盖请求生命周期、Transformer 推理机制、Benchmark、Profiling、Prefill、Decode、Serving 调度、RAG 与 Agent 的性能路径、容量与成本、生产工程。

**不讲**：训练侧的量化、蒸馏、剪枝；多模态与 VLM 推理；RAG 的检索算法本身和 Agent 的产品设计。RAG 与 Agent 只在“它们如何改变推理链路的延迟、吞吐、稳定性、质量与成本”这个角度出现。

## 动手实验

书里的实验分三档，按需要的硬件划分：

- **Level 1**：纯 CPU 即可。用于机制验证、公式检查和数据分析。
- **Level 2**：单张 GPU。大部分性能实验在这一档，示例模型是 `Qwen/Qwen2.5-0.5B-Instruct`，配 vLLM。
- **Level 3**：多 GPU 或多机。只出现在附录，不是读正文的前提。

没有 GPU 也能读完全书并完成 Level 1 的实验；涉及真机数据的地方会明确标出“待实测”，不会用编造的数字填充。
