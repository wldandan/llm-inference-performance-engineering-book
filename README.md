# LLM 推理性能工程与实践

> 从一次请求出发，建立可测量、可诊断、可验证的推理性能工程方法。

你把一个 LLM 服务跑起来了，用户说它慢。你打开监控，看到 P99 确实在涨。然后呢？

这本书讲的就是“然后呢”。它不是推理框架的使用手册，也不是优化技巧清单，而是一套能反复使用的工作方法：**怎样把“感觉慢”变成可以调查的问题，怎样拿到足以支撑结论的证据，怎样验证一次优化是真的有效还是只是噪声。**

我们把这件事叫作 LLM 推理性能工程：在守住质量底线的前提下，用可复现的证据，让大模型推理服务更快、更省地交付有用的回答。

## 为什么还要写这本书

现有的材料大致三类：框架文档讲怎么用，论文和博客讲某项技术为什么快，经验帖讲某个团队把参数调成了多少。中间那条线很少有人完整写出来：从“用户说慢”到“我能证明改完真的更快”。这本书补的是这条线，以及它上面的三个缺口：别人的结论换个场景还成不成立得自己判断；性能数字普遍缺前提；RAG 和 Agent 把链路拉长之后，“推理优化”这个范围不够用了。

缘起和这本书给自己定的五条约束，写在 [`content/preface.md`](content/preface.md)。

## 这本书给谁看

- **后端工程师 / AI 应用工程师**：服务是你部署的，出了性能问题要你查。
- **Agent 工程师**：一次任务背后有多次 LLM 调用，延迟和成本都在放大，你需要知道放大在哪。
- **MLOps / 平台工程师**：你要为一群应用团队规划容量、定 SLO、守住上线质量。

**需要你已经会的**：读基础 Python、JSON 和命令行输出；理解 HTTP 请求和基本并发；看得懂折线图和分位数。

**不需要预先掌握的**：CUDA、GPU 微架构、分布式训练、Transformer 的数学推导。这些在需要时会用够用的篇幅讲清楚，深入部分放在附录。

## 你会学到什么

读完之后，面对一个真实的推理服务，你应该能做到：

| 能力 | 具体是指 |
|---|---|
| **说清楚问题** | 把“服务慢”补成现象、范围、时间、对照四项，让它变成可以调查的东西 |
| **建立可信基线** | 跑出一份别人照着能重现的 Baseline，并知道它能识别多大的改善 |
| **找到那条请求** | 从一条告警下钻到具体的慢请求，而不是在聚合指标里猜 |
| **选对工具** | 知道一个现象该用哪一层的 profiling，以及上一层为什么不够 |
| **给出可证伪的结论** | 产出一份带排除项和残留不确定性的根因报告 |
| **估得出上限** | 在动手之前算出 Prefill 的量级、Decode 的搬运下限和这张卡装得下多少人 |
| **验证优化收益** | 用同一份负载重跑，区分真实改善和实验噪声 |
| **拆到整条链路** | 把 RAG 与 Agent 那半条链路分解开，按任务而不是按调用算账 |
| **算得出该配多少** | 从日活推到卡数和月账单，并说清哪个约束先满、余量买到了什么 |
| **守住已有的收益** | 定出不会持续误报的门禁阈值，让下一次变慢在上线之前就被拦住 |

贯穿全书有一条纪律：**没有证据就写没有证据**。缺失的阶段记为 `unavailable` 而不是 `0`，客户端观测不能直接当服务端事实，单次调用不能推出性能结论。这条纪律比任何具体的优化技巧都更值得带走。

## 全书结构

一章开篇，加上七个部分、三十章，围绕同一套真实服务逐层展开：

```text
运行  →  测量  →  诊断  →  优化  →  验证  →  上线守护
```

| Part | 主题 | 章节 | 读完能交付什么 |
|---|---|---|---|
| **开篇** | 推理性能的三条规律 | Ch0 | 三条贯穿全书的规律，以及判断一次优化算不算收益的标准 |
| **1** | 从一个请求理解推理系统 | Ch1–5 | 一次真实调用的生命周期证据报告，和一份十个字段的指标合同 |
| **2** | 测量、观测与根因分析 | Ch6–10 | 带随机种子的 workload 描述、可复现的 Baseline 与可识别线、一份根因报告 |
| **3** | Prefill 与上下文优化 | Ch11–14 | Prefill 的量级估算与实测对照，以及一轮含预期、护栏和边界的实验 |
| **4** | Decode、KV Cache 与生成优化 | Ch15–19 | TPOT 下限、一张容量表，和一份五维记分卡（质量是否决项） |
| **5** | Serving、RAG 与 Agent 性能工程 | Ch20–25 | 过载演练的 Goodput 曲线、全链路时间分解表、防回退断言 |
| **6** | 容量、成本与生产工程 | Ch26–29 | 能做假设分析的容量与成本模型、扩缩容配置、性能门禁与上线评审材料 |
| **7** | 综合项目 | Ch30 | 一套可运行、可观测、可解释、可优化、有门禁的完整服务 |

开篇不启动服务，也不写代码，推荐先读；已经熟悉推理基本原理的读者可以直接从 Part 1 开始，后面各章不依赖它。

每章的结构是固定的：章首给三个问题，正文逐一展开，章末回到这三个问题逐条作答，最后附一份可以打勾的自查清单。

GPU 架构与 Roofline、CUDA 与 Kernel Profiling、多 GPU、MoE、PD 分离放在附录 A 至 E，不占主线篇幅。全书用到的公式连同前提和失效点汇总在附录 F；术语表按定义所在的先后排列，同时标出每个词第一次出现的位置。

## 覆盖范围

**讲**：纯文本 Decoder-only 模型的在线推理，涵盖请求生命周期、Transformer 推理机制、Benchmark、Profiling、Prefill、Decode、Serving 调度、RAG 与 Agent 的性能路径、容量与成本、生产工程。

**不讲**：训练侧的量化、蒸馏、剪枝；多模态与 VLM 推理；RAG 的检索算法本身和 Agent 的产品设计。RAG 与 Agent 只在“它们如何改变推理链路的延迟、吞吐、稳定性、质量与成本”这个角度出现。

## 动手实验

书里的实验分三档，按需要的硬件划分：

- **Level 1**：纯 CPU 即可。用于机制验证、公式检查和数据分析。
- **Level 2**：单张 GPU。大部分性能实验在这一档，示例模型是 `Qwen/Qwen2.5-0.5B-Instruct`，配 vLLM。
- **Level 3**：多 GPU 或多机。只出现在附录，不是读正文的前提。

没有 GPU 也能读完全书并完成 Level 1 的实验：每一章的 Demo 都能在这一档跑通测试，换成自己的服务时再把合成样例替换掉。
