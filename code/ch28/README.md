# Chapter 28 Demo：性能门禁

`perf_gate.py` 做 28.3 的阈值判定和 28.4 的静默回退检查。四个子命令，全部离线：

```text
run        对着基线检查一次门禁运行，退出码可直接接进 CI
promote    换基线，要求写清为什么、谁签的字、属于哪一类
drift      28.1 那条累积退化：每次都在噪声里，半年后翻倍
threshold  从变异系数推出可用的阈值区间
```

## 1. run 会拦住一次“每项都更好”的运行

```bash
python3 code/ch28/perf_gate.py run \
  --result content/ch28/evidence/gate-result-silent.json \
  --baseline content/ch28/evidence/gate-baseline.json \
  --thresholds content/ch28/evidence/gate-thresholds.json
```

```text
  p50_latency_ms             392  基线 420       变化 -6.7%  阈值 5%
  p95_latency_ms             918  基线 980       变化 -6.3%  阈值 10%
  p99_latency_ms            1690  基线 1740      变化 -2.9%  阈值 —  仅观察
  throughput_tps            1639  基线 1560      变化 +5.1%  阈值 5%
  peak_memory_gib           48.7  基线 61.2      变化 -20.4%  阈值 2%
断言              有，未通过 ['attention_kernel_allowlisted']
质量              需要 True，有 False，越界 False
结论              fail（退出码 1）
阻断原因          断言未通过：['attention_kernel_allowlisted']；这次改动动了精度却没有质量数据（28.4 第一类）
```

**五个指标全都更好，显存还降了两成，仍然以退出码 1 结束。** 这是 28.4 的核心：静默回退不会体现在延迟指标上。这份样例踩了两类：一条断言没通过（用了不在白名单里的 attention kernel），以及改了精度却没有附质量数据。

一份“什么都更好”的报告是最该被怀疑的那种报告，所以仓库里专门放了这一份而不只是放一份正常通过的。

## 2. 阈值不能落在噪声里

```bash
python3 code/ch28/perf_gate.py threshold --cv 0.026
```

28.3 原则一：阈值至少要是变异系数的两倍，推荐三倍，取整到百分位。变异系数 2.6% 时推荐 8%；变异系数 9% 时 5% 的阈值根本没法用，`check_threshold_sanity()` 会当场拒绝这次运行而不是给出一个随机的红绿。

它还打印这个阈值的代价，按 `gate_error_rates()` 算：两边各跑一轮时差值的波动是 `√2 × CV`，没有回归时越过阈值的概率就是单个指标的误报率，五个指标一起判是 `1 − (1 − p)^5`；真实回归为某个幅度时越过阈值的概率就是检出率。2.6% 和 8% 给出单指标误报约 1.5%、五个约 7%、8% 的回归检出 50%，两边各跑 3 轮时 10% 的回归检出约 83%。另外报出第 7.3 节那条可识别线（各 3 轮时约 5.9%），阈值不能低于它。

28.8 案例一就是这条：先把变异系数从 9% 压到 2.6%，阈值才谈得上设多少。

默认阈值表按 28.3 给：P50 5%、P95 10%、吞吐 5%、峰值显存 2%。**P99 只观察不阻断**，它的波动本来就大，拿它做门禁只会让人学会忽略门禁。

## 3. 环境指纹不一致，直接不构成对比

`check_run()` 要求 `environment` 四项齐全（GPU、框架版本、模型、负载哈希），缺一项就报错；其中 GPU、模型、负载哈希三项还要逐字相同，不同就报错。框架版本只记录、不比对，因为框架升级正是门禁要拦的候选变更之一（28.2 条件二把环境分成“钉死的”和“被测的”两类）。跨环境的两个数放在一起比，比不比都一样。

没有任何断言时它降级为 `warn`（退出码 2）而不是 `pass`，因为一次没有断言的门禁运行只是在量，不是在守。

## 4. promote 要求写清三件事

```bash
python3 code/ch28/perf_gate.py promote \
  --result ... --baseline ... \
  --reason "Ch17 KV INT8 验收：理论并发 213 → 427，质量评测通过" \
  --approver mango --kind improvement
```

少 `--reason`、少 `--approver`、`--kind` 不是 `improvement` 或 `accepted_regression`，三种情况都拒。**没通过的运行不能成为新基线**，这一条堵的是 28.8 案例二那条路：门禁一直红着，有人把当前结果设成基线，于是门禁变绿了，而系统比半年前慢了一倍。

## 5. drift：每次都在噪声里，累积不在

```bash
python3 code/ch28/perf_gate.py drift --steps 0.05,0.04,0.06,0.05,0.04
```

```text
  第  5 次  +5.0%   累计 1.264 倍
解读              5 次退化累积成 1.26 倍，平均每次 4.8%
```

28.1 那五步连乘是 **1.26 倍，不是两倍**。两周一次发布，26 周是 13 次：`1.05^13 ≈ 1.89`，也就是 28.8 案例二那个“半年慢了将近一倍”。`steps_to_double()` 给出 5% 每次要 14.2 次、8% 每次要 9.0 次。

**这两个数不能混。** 五步的累积效应是“门禁一次都不会响”，半年的累积效应是“系统慢了一倍”，它们是同一条机制在两个时间尺度上的结果，写成同一个数字就等于把 28.1 的论证做坏了。

四份样例都是**合成设定**。两份结果文件共用同一份 `environment`，测试核对这一点，否则对比不成立。
