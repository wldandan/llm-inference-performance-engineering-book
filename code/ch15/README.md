# Chapter 15 Demo：Decode 性能估算器

`decode_model.py` 把这一章那条搬运下限算出来，再把下限漏掉的那一块（KV Cache 的读取）加回去，报告两者在哪个批量和上下文下交叉。

**它不测量任何东西。** `--measured-tpot-ms` 是你从真实 Baseline 拿来的数字；不给它，报告就只有理论一侧，并且会写明不给解读。

只依赖 Python 标准库，不需要 GPU。

## 1. 共享配置

`model-7b-generic.json` 是 **Part 4（第 15-19 章）共享的通用 7B 配置**。这五章的 Demo 都读它，Part 4 正文里所有与这个模型有关的数字都出自它：

```text
权重          14 GB（十进制）= 13.04 GiB（二进制）
单步下限      14 GB ÷ 1000 GB/s = 14 ms，对应每秒 71.4 个 token
每 token KV   2 × 32 × 8 × 128 × 2 = 131072 字节 = 128 KiB
```

和第 11 章那份 `model-qwen25-05b.json` 的关系：那一份是**本书的小模型**，取自真实的 Qwen2.5-0.5B；这一份是**通用示例**，参数是这个规模上常见的形状，不对应某个具体的开源模型。前四章用小模型把机理讲清楚，这五章换成 7B 是为了让显存和延迟数字落在更常见的量级上，而第 15.2 节那个恒等式与模型多大无关，所以换模型不影响结论。

换模型只改这一份文件。**不要在五章正文里各改一遍**，那正是 2026-09-22 那轮审阅查出的六处数字不一致的来源。

## 2. 运行

```bash
python3 code/ch15/decode_model.py \
  --config code/ch15/model-7b-generic.json \
  --batch 1,8,32,64 \
  --context 512,4096,16384 \
  --measured-tpot-ms 17
```

想看 15.2 那个分界点，要给一对同一张卡的规格：

```bash
python3 code/ch15/decode_model.py --a100 --bandwidth 2039 --batch 1,32,153
```

## 3. 两处刻意的设计

**两套单位口径都标在报告里。** 权重与带宽是十进制（GB = 10⁹），因为两边都是厂商口径，相除正好约掉；显存占用是二进制（GiB = 2³⁰），因为那是分配器和框架日志的口径，第 16 章要接着算容量。`units` 字段把这件事写明，第 16.2 节把它说破。

**分界点要一对配套的规格，否则不算。** `--peak-tflops` 和它配对的带宽必须来自同一张卡：用 A100 的算力除以另一张卡的带宽，算出来的分界点没有意义。所以不给 `--peak-tflops` 时，`balance_point_flops_per_byte` 和 `crossover_batch` 都留空，而不是拿 `--bandwidth` 凑一个数出来，因为 `--bandwidth` 常常是 15.3 那个取整的教学值 1000 GB/s。

## 4. 三个用法

**看批量的边际收益。** 从 1 到 8 吞吐涨得很猛，从 32 到 64 就明显缓了。`crossover_batch` 给出这条曲线的转折位置：A100 的分界点是 153 FLOP/byte，FP16 下交叉批量就是 153，越过之后加批量会真的变慢，报告会给出警告。

**看上下文对批量收益的侵蚀。** 固定批量把 `--context` 拉大，会看到 `kv_over_weight` 越过 1，那一行被标上“KV 已超过权重”。批量 32、上下文 8000 时 KV 是 31.25 GiB，超过 13 GiB 的权重，这就是 15.7 说的“Attention 成了主导”。

**和实测对照。** `comparison.reading` 按 15.5 分四档：比值小于 1 是口径有问题（下限已假设带宽满载，比它快说明边界定义有误），1.3 以内是带宽受限，2.0 以内是混合，再往上是调度受限。


46 项测试。除了常规校验，它们把正文里的每个数字都钉在了代码上：15.2 的 1 / 2 / 4 FLOP/byte 与 153 分界点、15.3 的 14 GB / 13.04 GiB / 14 ms / 71.4 tps、15.4 的 0.4375 ms 与 153 交叉批量、15.7 的 1000 MiB 与 31.25 GiB、15.6 的 17 除 14、17.8 案例一的 6.25 倍。正文改了而代码没改，或者反过来，测试会失败。
