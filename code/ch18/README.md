# Chapter 18 Demo：Decode 优化适用性检查

`decode_optimization_check.py` 先判瓶颈形态，再拿三项技术逐个对着形态判，并且**拒绝猜那个唯一决定投机解码的数字**。

只依赖 Python 标准库，不需要 GPU。

## 1. 运行

```bash
python3 code/ch18/decode_optimization_check.py \
  --config code/ch15/model-7b-generic.json \
  --tpot-measured 25 \
  --batch-p50 8 --batch-p95 32 \
  --draft-params 0.7e9 \
  --captured-buckets 20 \
  --draft-acceptance content/ch18/evidence/draft-acceptance-sample.json
```

`--tpot-floor` 不给就按配置里的参数量和带宽自己算，省得两处各写一遍。

## 2. 四件刻意的事

**接受率没测过就不给预估，而且这条压过其他判据。** 其他判据全部有利时，缺 `--draft-acceptance` 仍然只能是“待测”。接受率取决于内容的可预测性，是业务属性，在场景之间完全不可迁移，所以行业平均值比沉默更糟。

**盈亏线和收益比一起报。** 18.3 那个式子是 `a ÷ (1 + k × c)`，盈亏线是 `a > 1 + k × c`。k=4、c=0.1 时线在 1.4：低于它是**净亏损**，不是收益小。

**高批量下是前提失效，不是公式失灵。** 给了实测接受率而批量又超过 分界点 ÷ (k + 1)（参考卡、k = 4 时约 31）时，脚本照样把收益比算出来，同时说明这个数在这个批量下不成立：分母里那个 1 代表“验证近乎免费”，算力不空闲时它会变大。18.8 案例一那 8 个百分点的缺口就藏在这里。**脚本不改数字，改的是对数字的解读。**

**CUDA Graph 那条模型大小的线是算出来的，不是写死的 30B。** 启动开销固定在每步 0.5 ms，单步下限随参数量线性涨，把“占比低于 1%”当成线，解出来：

```text
0.5 ms ÷ 下限 = 1%  →  下限 = 50 ms  →  50 ms × 1000 GB/s ÷ 2 字节 = 25B
```

1000 GB/s 的卡上落在 25B，2039 GB/s 的卡上落在 51B。**带宽越高，同样参数量下单步越短，启动开销占比越大，CUDA Graph 反而越值得做。** 这条线是卡的属性。

## 3. 尝试顺序会随瓶颈形态换

第一步永远是 15.5 那个对照。之后：瓶颈在调度就先走 CUDA Graph，瓶颈在带宽就先评估投机解码。kernel 层永远最后，且标为确认项而不是改动项。

## 4. 那份合成的接受率样例

`draft-acceptance-sample.json` 是**合成样例，不是真机结果**。它同时给了盈亏线两侧的场景：

```text
code-completion        3.6   线上方，值得开
json-extraction        3.1   线上方
customer-service-chat  1.3   线下方，开了会更慢
open-ended-writing     1.1   线下方
```

这就是 18.8 案例一的两半：同一套配置，客服对话慢 7%（式子给的）到 15%（实测的，多出来的是批量 40 那一项），代码补全快 61%。

## 5. 测试

```bash
python3 -m unittest discover -s code/ch18 -p 'test_*.py'
```

63 项测试。18.3 的 1.4 盈亏线与 2.286 / 0.786 两个算例、1.3 GiB 草稿与 1.1 万 token；18.4 的 3.57% 与 0.83%、25B 与 51B、图捕获显存只从启动日志读而不按档位数相乘；α 与 a 的换算、最优 k、批量阈值 = 分界点 ÷ (k + 1)；18.6 那张表的三个阈值；18.8 案例一两半的 0.93 与 2.571，以及“同一配置在两个场景给出相反结论”这一条。

接受率报告可以给平均接受长度 `mean_accepted`（a），也可以给引擎常报的逐位置接受率 `acceptance_rate`（α），脚本会按 a = (1 − α^(k+1)) ÷ (1 − α) 换算并报出最优 k。图捕获显存用 `--graph-memory-gib` 传启动日志里的数。在自己的服务上测出接受率后，替换合成样例，再拿实测收益去对 18.3 那个收益比公式。
