# 模块四：分布式推理架构

**学时**：8学时（4讲 × 2学时）  
**定位**：掌握大规模多卡推理集群的架构设计与调度原理

---

## 本模块教什么

本模块回答一个问题：**当一台机器放不下模型，或者一台机器的性能不够用，怎么正确地把推理任务拆分到多台机器上？**

从四个维度系统拆解：

| 讲次 | 主题 | 核心问题 | 关键结论 |
|------|------|---------|---------|
| 讲1 | Tensor并行与Pipeline并行 | TP/PP有什么区别？如何组合？ | TP减少单层延迟，PP增加整体吞吐，3D并行叠加 |
| 讲2 | Prefill-Decode分离架构 | 为什么把Prefill和Decode分开部署？ | 两阶段资源需求不同，分离后各自优化 |
| 讲3 | 推理集群调度与负载均衡 | 如何让每台机器都不空转？ | 路由策略+优先队列+背压机制三层设计 |
| 讲4 | 多模型路由与成本优化 | 如何用最低成本服务不同质量需求的请求？ | RouteLLM按需路由，Serverless弹性扩缩 |

---

## 核心直觉（直觉类比总结）

| 技术 | 类比 | 本质 |
|------|------|------|
| Tensor并行 | 并行车间同时加工一件产品 | 单层计算拆分，减少单步延迟 |
| Pipeline并行 | 流水线工位分工 | 不同层在不同GPU，提升整体吞吐 |
| Pipeline气泡 | 流水线等待导致工位空转 | PP的主要效率损失 |
| PD分离 | 前台接单与后厨制作分开 | Prefill/Decode资源需求差异巨大 |
| 负载均衡 | 交通调度中心分流 | 请求均匀分发，避免热点 |
| 多模型路由 | 聪明的外包策略 | 简单任务用小模型，复杂任务用大模型 |

## 分布式推理架构速查

```
并行策略选型：
├── 单机多卡（≤8卡）
│   ├── Tensor Parallel (TP=4/8) — 减少延迟
│   └── TP=8 为 A100/H100 单机上限
├── 多机多卡
│   ├── Pipeline Parallel (PP) — 跨机器，注意气泡率
│   └── TP+PP 组合（3D并行加入SP/EP）
└── 超大规模
    └── TP+PP+EP(MoE) 三维并行

PD分离选型：
├── 单机服务 → 不分离（开销不值得）
├── 中等规模 → 异质化部署（Prefill用A100，Decode用L40S）
└── 大规模集群 → Splitwise/Distserve架构
```

```
并行原理 → 分布式实现 → 调度系统 → 成本优化
```

**必读论文（按优先级）**
1. Megatron-LM (Narayanan et al., SC 2021) — TP/PP基础
2. Splitwise (Patel et al., ISCA 2024) — PD分离架构
3. Distserve (Zhong et al., OSDI 2024) — PD分离系统实现
4. RouteLLM (Ong et al., 2024) — 多模型路由
5. Orca (Yu et al., OSDI 2022) — 推理调度基础
