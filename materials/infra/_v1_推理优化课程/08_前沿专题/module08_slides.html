第1讲 · Reasoning模型

KV Cache 爆炸：三大应对策略

策略1：KV 压缩

  • SnapKV：保留重要位置的KV，压缩率 10×
  • H2O：Heavy Hitter Oracle，动态淘汰低权重KV
  • StreamingLLM：滑动窗口 + Attention Sink
  • 代价：轻微精度损失 (1-3%)

策略2：Thinking Budget

  • DeepSeek-R1 参数：max_thinking_tokens
  • Claude 3.7：budget_tokens 参数
  • 动态预算：简单问题少想，复杂问题多想
  • 效果：显存可控，质量小幅下降

策略3：早停策略

  • 置信度检测：答案收敛即停止
  • Speculative Thinking：快速草稿 + 精细审阅
  • Budget-Aware Scheduling
  • 效果：平均节省 30-50% Thinking Tokens

DeepSeek-R1：Reasoning模型工程实践

关键 Infra 挑战

1

超长序列显存管理

单请求 KV Cache 可达数 GB，PagedAttention 页面数量爆炸，需要更激进的显存换出策略

2

Decode 阶段极长

Prefill 只占总时间 1-5%，Decode 占 95%+，PD 分离对 Reasoning 模型价值更大

3

批调度复杂性

同批次请求推理链长度差异极大（100 tokens vs 30K tokens），动态批调度挑战

4

优化效果

PD 分离 + KV 压缩 + 早停：端到端延迟降低 40%，成本降低 35%

第2讲 · 下一代AI Infra

算法前沿：Attention的持续进化

Flash Attention 3（2024）

关键改进

  • Hopper 异步特性：WGMMA + TMA 双流水
  • FP8 支持：H100 专属低精度加速
  • 性能提升：较 FA2 提升 1.5-2×
  • 实测：A100 75% 峰值带宽利用率 → H100 85%+
# FA3 目前集成在 vLLM / SGLang # H100 自动启用 FA3 python -m vllm.entrypoints.api_server \ --model ... \ --attention-backend flash_attn_3 # FA3

MLA（DeepSeek-V3）

Multi-head Latent Attention

  • 核心思想：将 KV 投影到低秩潜空间
  • 效果：KV Cache 压缩 5-13×
  • 精度损失：几乎无损（<0.5%）
  • 意义：解决了长上下文 KV 瓶颈
MLA 直觉

不存储完整 KV，只存储"压缩摘要"，需要时再解压——以计算换存储。

第2讲 · 下一代AI Infra

Test-Time Compute Scaling

核心思想

训练时计算 Scaling（更大模型）遇到成本天花板。Test-Time Compute Scaling：推理时给模型更多计算，输出质量持续提升——这是 o1/R1 系列背后的核心范式转变。

思路1

Best-of-N 采样

生成 N 个答案，选最优。N=8 时准确率提升约 15%，成本 8×

思路2

树搜索 (MCTS)

推理步骤级别的搜索，找最优推理路径。AlphaCode2 的核心

思路3

CoT 推理链

o1/R1：让模型自主决定何时停止推理，兼顾质量与成本

方法质量提升成本倍数适用场景

Best-of-8+15%8×高价值任务

MCTS+35%50×+研究/复杂问题

存算一体：终极解决内存带宽墙

冯·诺依曼瓶颈

现代 GPU：算力 1 PFLOPS，但内存带宽只有 ~3 TB/s。Decode 阶段每步需要读一次全部权重，大模型已是"搬运工"而非"计算机"。

现在

计算与存储分离

数据搬运占主导，GPU 利用率 30-50%，实际有效算力极低

未来

存算一体（PIM/CIM）

在内存中直接计算，带宽提升 100-1000×，推理功耗降低 10×

当前进展（2024-2025）

  • Samsung HBM-PIM：已量产，AI加速 2×
  • SK Hynix AiMX：推理专用，功耗降低 60%
  • UPMEM：通用 PIM，适合 embedding lookup
  • 学术界：已验证大模型推理 10-100× 提升

产业化时间线

  • 2025：HBM-PIM 量产集成
  • 2026：主流服务器标配
  • 2027+：专用 LLM 推理芯片
