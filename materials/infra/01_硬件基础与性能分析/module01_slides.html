为什么从硬件开始？

优化 = 找瓶颈 + 消瓶颈
AI系统的瓶颈几乎总藏在硬件特性里，不理解硬件，优化等于在黑箱里调参数。
  • GPU有计算上限（峰值FLOP/s），不能超越
  • GPU有带宽上限（HBM GB/s），不能超越
  • 任意算子只能是两个上限中的较小者
  • Roofline图帮你找到"你在哪里、能优化多少"
  • 后续所有模块都是：把某个op从低效区推向Roofline

SM / Warp：工厂流水线

类比：工厂流水线

H100有132条独立流水线（SM），每条流水线上有若干工组（Warp），每组32个工人同时做同一件事。

  • SM（Streaming Multiprocessor）：GPU最小独立计算单元
  • Warp：32个线程，SIMT执行，必须执行同一指令
  • Warp分歧：if/else导致串行，效率减半
  • Occupancy：SM上同时"在跑"的Warp数，越高越好
  • H100每个SM有64KB L1/Shared SRAM

Tensor Core：专职速算员

类比：专职速算员

CUDA Core能做任何运算，Tensor Core只会做矩阵乘法（GEMM），但快得离谱——相当于雇了16个专职乘法员顶替1个通才。

  • 每个Tensor Core每周期计算一个16×16×16矩阵乘
  • H100 Tensor Core支持：FP8 / FP16 / BF16 / TF32 / INT8
  • FP8 = 最新格式，H100新增，算力是FP16的2倍
  • Transformer Engine：自动选择FP8/FP16，运行时动态调整
  • CUDA Core仍负责：标量运算、控制流、激活函数

NVLink vs PCIe：高速公路 vs 普通公路

类比：道路系统

NVLink是城市内环高速（900GB/s，低延迟，专为GPU设计），PCIe是普通省道（128GB/s，共享，CPU主导的老路）。Tensor并行必须走内环高速。

  • NVLink 4.0：H100间双向900 GB/s，延迟~1μs
  • NVSwitch：全互联交换芯片，DGX H100 8卡全连接
  • DGX H100系统：3.6 TB/s 全互联带宽
  • PCIe 5.0 ×16：128 GB/s，CPU-GPU通信仍是瓶颈
  • Tensor Parallel跨卡AllReduce：必须走NVLink

带宽如何决定推理上限

具体案例：LLaMA-70B 单卡推理（Batch=1）

模型权重约140GB（FP16），每生成一个token，需要将所有权重从HBM读一遍 → 140GB ÷ 3.35TB/s ≈ 42 ms/token，即理论最高24 tokens/s（单卡，不含计算）。

tokens/s ≤ HBM带宽 / 每token读取字节数 = BW / (2 × params × bytes_per_param)
  • Batch=1时，推理几乎100%Memory-Bound
  • Batch增大 → 计算量×Batch，读权重一次共享 → 逐渐变Compute-Bound
  • 量化到INT4：权重缩小4倍 → 读取时间缩小4倍 → 吞吐量4×
  • KV Cache大小 = seq_len × layers × heads × head_dim × 2 × bytes
~5%
Batch=1推理的Tensor Core利用率
大部分时间在等HBM数据，而不是计算
这就是为什么推理优化的核心是增大Batch（提高算术强度）和量化（减少字节数）。

类比：工厂排班

Dense = 每个token让所有工人上班，成本高但质量稳定；MoE = 每个token只派最合适的2位专家，省钱但调度复杂。

MoE的Infra挑战：
1. 每个Expert需要单独加载到GPU → 显存 = 总参数而非激活参数

Transformer各层：算力 vs 带宽需求

层类型 Batch=1特性 Batch=32特性 瓶颈 优化方向
Linear (FFN) Memory-Bound Compute-Bound 小batch读权重 量化 / 增大batch
Attention (QKV Proj) Memory-Bound Compute-Bound 同Linear GQA / 量化
Attention (QK Softmax) Memory-Bound Memory-Bound（KV） KV Cache带宽 FlashAttention / MLA

Softmax + 激活 Memory-Bound Memory-Bound 逐元素操作 Kernel Fusion
核心洞见：Batch=1时，Transformer几乎全部操作都是Memory-Bound（等待HBM）。增大Batch到临界点（Ridge Point）后，FFN才变成Compute-Bound。Attention在长序列下始终是Memory-Bound。
讲3 · 模型架构

GQA / MLA：减少KV内存压力

MHA
Multi-Head Attention（原版）
每个head独立KV，KV Cache随head数线性增长
  • 32个Q head → 32个KV head
  • KV Cache = H × D_kv × S × L × 2 bytes
  • LLaMA-70B: ~80GB KV Cache (seq=32K)
GQA
Grouped Query Attention
多个Q head共享一组KV head，减少KV数量
  • 32Q head → 8 KV head（4倍压缩）
  • 显存减少4×，带宽需求减少4×
  • LLaMA-3：默认使用GQA
MLA
Multi-head Latent Attention
DeepSeek创新：低秩压缩KV，极致节省显存
  • KV压缩到低秩潜变量 C_KV
  • 相比MHA：KV Cache缩小约5-13×
  • DeepSeek-V2/V3：使用MLA
MHA KV: H×D → GQA KV: H/g×D → MLA KV: c（低秩）

实验核心工具

Roofline模型：找到优化上限

类比：员工绩效图

横轴是"每次出门办多少事"（算术强度 FLOPs/Byte），纵轴是"总产出"（FLOP/s）。屋顶是硬件上限：左边斜坡 = 带宽限制，右边平台 = 计算限制。

  • 算术强度（AI） = FLOPs / Bytes
  • Ridge Point = 峰值算力 / 峰值带宽
  • H100 Ridge Point ≈ 989TFLOP/s ÷ 3.35TB/s ≈ 295 FLOPs/Byte
  • AI < Ridge Point：Memory-Bound，优化带宽利用率
  • AI > Ridge Point：Compute-Bound，优化算子效率
性能上限 = min(峰值算力, AI × 峰值带宽)

模块一：3个核心结论

01

所有AI算子都受制于两个上限：计算上限和带宽上限

用Roofline图能在30秒内判断任意算子的瓶颈所在，以及理论优化上限。这是所有Infra优化的出发点。

02

LLM推理在小Batch下几乎全部是Memory-Bound

Batch=1时，Transformer各层等待HBM的时间远大于计算时间。增大Batch和量化是最有效的推理加速手段，本质上都是提高算术强度。

03

模型架构决定硬件需求，反之亦然

Dense模型需要高算力，MoE模型需要高带宽互联，长序列需要GQA/MLA减少KV Cache。架构选型和硬件选型是相互约束的系统工程问题。
