# 本机 Ollama 与内存观测（2026-09-29）

用户已确认沿用现有 Python 后端集成资源采集，不需要安装 Prometheus。
本轮只实现无提权的 Ollama 与系统内存采集；GPU 特权采样不自动启动，KV 不推算。

## 验收条件 /sm

- `telemetry.local.enabled` 默认 false，旧配置和未启用的实验没有新增采集访问。
- 仅主动启动实验后采集，停止、取消、异常结束后关闭；观察频率沿用 `interval_s`。
- 启用时仅接受 loopback 模型服务的根路径或 `/v1`，仅 GET 同源 `/api/ps`。
- 界面明确采集的是后端所在主机；用户确认模型就在该主机，端口转发/远程机器不能等同本机。
- 按模型名称匹配；未加载、无字段、非法值、认证/网络/协议失败使用 null 和固定原因，不回显异常原文。
- 系统总/可用内存与 Swap、模型内存与配置上下文分别命名；不得充当设备显存或 KV 使用率。
- 模型源失败仍保留系统采样和已有 Prometheus 观测；不复用前次成功数值。
- JSONL 兼容现有存储、查询与脱敏导出；结果展示最新状态、采样时间与时间序列表，旧实验仍可查看。
- 测试只使用本地协议端点，不启动真实生成、不下载模型、不连接 GX10/Ascend、不提权运行 GPU 工具。

## 设计 /arch /ui

在 `local_telemetry.py` 封装两类只读采样；复用 TelemetryCollector 的启停与追加存储。
两类 source 为 `local-system` 和 `local-ollama`，使用 `source_kind` 标识本地来源。
采样顺序为 system、ollama、原有 exporter，每次失败隔离；有超时，无积压补发，不承诺精确周期。
HTTP 限制响应大小、超时、禁止重定向及代理；沿用密钥环境变量且不落盘。
系统内存通过 psutil；GPU 继续允许用户通过已有 exporter 接入，本轮不新增特权进程。
前端增加默认关闭的复选框及复用小号问号，资源页沿用已有样式、增加概要与可展开数据表/原始 JSON。

审批：Faraday 的 /sm、/arch、/ui 已批准。来源按类型与名称隔离，停止返回后无写入，最新失败不得回退到历史成功值；界面明确模型同机确认与 GPU/KV 边界。
