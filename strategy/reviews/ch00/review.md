# Chapter Review

## 总体评价

第 0 章是全书唯一零前置的原理章，不启动服务、不写代码。它从模型 API 价目表上的三个差价和“快、省、好”三个人的诉求切入，依次讲清模型是什么（0.2）、一个请求里写为什么比读贵（0.3，第一条规律）、很多请求共用一张卡时批量与排队的冲突（0.4，第二条规律）、什么才算优化（0.5，第三条规律），最后给出 LLM 推理性能工程的定义与“规律只给假设，结论要靠测量”（0.6）。章首三问在本章总结中逐条作答，三个案例和两个误区分别检验三条规律。

定位为“推荐先读，跳过也能读后面”：README 与 `content/index.html` 已加开篇入口，第 5.4、15.3、20.6 节已写入回针句，回针句自带规律内容，不依赖读者读过第 0 章。

## 结构问题

未发现阻塞问题。

- 七节顺序按尺度放大：现象、模型、单请求、多请求、什么算数、怎样证明、案例，与全书从单实例到服务集群、再落到证据的走向一致。
- 三条规律各在所在小节点名一次，0.6 并列汇总时措辞一致。
- 价目表的三个差价由规律一（输出更贵、缓存命中便宜）和规律二（愿意等更便宜）回答；开场“快、省、好”三个人在 0.5 点名规律三时收回。
- 0.5 以“把卡用满、让吞吐涨上去，就算优化成功了吗”开场，依次展开有用的产出、成本式子、质量底线、快不是目标，最后落到规律三与性能定义。
