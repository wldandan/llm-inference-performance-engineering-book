# Part 7 综合项目（Capstone）

## 本篇导读

前二十九章是分开学的。这一篇只有一章，把它们用在同一件事上。

分章学习有一个天然的问题：每一章都在一个干净的前提下讨论一个孤立的问题。而真实的工作不是这样的，真实的工作是有人说“这个服务慢，你看看”，而所有的前提都要你自己去建。

这一篇要检验的正是这个：**给你一条真实链路和一组 SLO，你能不能自己把顺序排出来、把证据建起来、把结论说清楚。**

## 本篇主线

```text
一个从零开始的服务
  -> 跑起来并说清楚          Ch1-Ch5
  -> 把负载和基准立住        Ch6-Ch7
  -> 让系统可观测            Ch8-Ch10
  -> Prefill 与上下文        Ch11-Ch14
  -> Decode 与显存           Ch15-Ch19
  -> 服务与链路              Ch20-Ch25
  -> 容量、门禁与评审        Ch26-Ch29
```

七个阶段，就是前六篇的顺序。**这个顺序不能大幅打乱**，因为后面每个阶段都依赖前面的产出：没有 workload 就没有 Baseline，没有 Baseline 就没有门禁，没有容量模型就没有成本讨论。

## 本篇章节关系

| 章节 | 本章完成什么 | 明确不做什么 |
|---|---|---|
| Chapter 30 端到端性能工程项目 | 五项交付物、七个阶段、报告契约、八条自查 | 不引入任何新技术 |

## 本篇靠哪条道理

主线位置：整条主线走一遍，从运行到上线守护。和第 0 章的关系：本篇这条道理是第 0 章第三条规律的终点。第 0 章说“只有有用的产出才算数”，并把性能定义成快、省、好三者之间的一个位置；这一篇要做的就是在一条真实链路上把那个位置挪一次，并说清每一步换走了什么。

前六篇各有一条自己的道理，这一篇只剩一条，而它是前面六条的公约数：**快、省、好三者互相拉扯，任何一次优化都是一笔交换，交换不会因为手法高明而消失。** 本书称之为折中不可消除。

判据只有一句：每一项改动都要写出它换走了什么。批量换走 ITL 的稳定，量化换走一部分质量，缓存亲和换走负载均衡，余量换走成本，准入换走一部分请求。写不出交换的改动只有两种可能，一是真的白拿，二是代价还没被测到。下面那八条自查，查的就是第二种。

它在什么地方不成立：白拿确实存在，但都落在“本来就错了”这一类，比如 prompt 拼接顺序反了导致缓存全不命中、`max_model_len` 设成了实际长度的十倍。所以每次优化之前先找一遍这类错误，它们不需要付代价，也就不需要权衡。往后本篇最末那四条，是这条道理去掉具体数字之后剩下的东西。

## 交付要求

**五项交付物：**

```text
可运行   服务能起来，有明确的启动和验收步骤
可观测   请求级追踪、关键指标、能从聚合下钻到单条
可解释   每个性能数字都能说清它测的是什么、在什么条件下得到的
可优化   至少完成一轮完整的"定位 → 改动 → 验证"闭环
有门禁   自动 Benchmark 加断言，能拦住性能回归
```

**规模不重要，完整性重要。** 单卡、小模型、几百条文档的知识库完全可以，重要的是这条链上每一环都真实存在，而不是某几环用假数据糊过去。

**Core 与 Advanced 共用同一份报告契约。** Advanced 学员可以把单卡换成多 GPU、把稠密模型换成 MoE、把一体化部署换成 PD 分离，但沿用同一份 workload、同一组 SLO、同一套验收标准。实现细节在附录 C、D、E。

## 验收的八条自查

这八条对应全书出现频率最高的几类错误：

```text
1. 有没有把"不可用"写成 0
2. 有没有把客户端观测当成服务端事实
3. 每个性能数字有没有对应的条件（批量、上下文、缓存状态、冷热）
4. 有没有"测不出来"这个结论
5. 护栏指标是不是每轮都记了
6. 有没有一次改了多项
7. 质量有没有被当成否决项
8. 边界写了没有
```

**任何一条不过关，整份报告的可信度都要打折**，因为读的人会开始怀疑其他部分。

## 学完本篇你应该能做到什么

- 独立排出一个性能工程项目的推进顺序，并说明每一步依赖前一步的什么；
- 为每个阶段定出可检验的验收判据，而不是“做完了”；
- 产出一份含九块内容的完整报告，包括边界与未验证项；
- 用八条自查发现自己报告里的可信度缺口；
- 判断一份别人的性能报告是否站得住，指出它缺了什么；
- 在报告里保留失败的和不可分辨的实验，并说清它们的价值；
- 把这套方法迁移到换了模型、换了硬件、换了框架的场景。

## 最后

具体的技术会换代，公式里的常数会变，框架的参数名会改。这门课真正想留下的是几条更硬的东西：

```text
不可复现的数据比没有更糟
证据不足就写不足
测不出来也是结论
任何收益都绑定在它成立的边界上
```

这四条不依赖任何特定的模型、框架或硬件，**它们比这本书里的任何一个数字活得都久**。
