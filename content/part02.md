# Part 2 测量、观测与根因分析（Measure, Observe, Diagnose）

## 本篇导读

Part 1 结束时，你能启动一个服务、跑通一次调用、说清它的生命周期、画出组件职责，并用统一口径描述结果。但那些都建立在**一条请求**上。

线上问题不是这样来的。用户说慢，你面对的是每秒几十条请求、长度参差不齐、到达时间不均匀的真实流量。这时候最先卡住的往往不是技术，而是问题本身没被说清楚：慢多少、哪些请求、和什么比。

本篇要做的，是把“感觉慢”一路收敛成“一份别人能复核的根因报告”。中间每一步都在回答一个具体的缺口：负载没定义、数字不可复现、请求找不到、内部看不见、结论不可证伪。

## 本篇主线

```text
一条请求（Part 1 的终点）
  -> 先说清楚负载是什么          Ch6
  -> 让一个数字可以被复现        Ch7
  -> 把一条请求的痕迹找齐        Ch8
  -> 需要时再打开系统内部        Ch9
  -> 把现象收敛成可证伪的结论    Ch10
```

五章是一条单向的链，每一章都为下一章准备输入：没有 workload 描述，Baseline 不可复现；没有可复现的 Baseline，改动的收益无法判断；没有请求级追踪，只能在聚合指标里猜；没有分层 Profiling，请求级解释不了的现象就到头了；而前面四样齐了，根因分析才有材料可用。

反过来看也成立：**Part 2 的产出是一份诊断报告，不是一组互相孤立的工具截图。** 如果最后交出来的是几张火焰图和 Dashboard 截屏，说明这条链没有走通。

## 本篇章节关系

| 章节 | 本章完成什么 | 明确不做什么 |
|---|---|---|
| Chapter 6 LLM 工作负载建模 | 把负载写成含长度分布、到达模式、并发和 SLO 的描述文件 | 不发送请求，不产生任何性能数字 |
| Chapter 7 Benchmark Design | 用这份描述跑出可复现的 Baseline：Warmup、重复、窗口、环境指纹 | 不做优化对比，不解释为什么慢 |
| Chapter 8 请求级可观测性 | 用一个 Request ID 贯通客户端、服务端日志、指标和 Trace | 不搭建监控平台，不讨论告警策略设计 |
| Chapter 9 Profiling Toolchain | 按四层选择工具，并标注采集条件与开销 | 不深入 Kernel 级分析，那在附录 |
| Chapter 10 Root Cause Analysis Lab | 走完假设、证据、排除、结论、最小改动的完整流程 | 不实施具体优化技术，那从 Part 3 开始 |

四章方法加一章实践。前四章各自建立一种能力，第 10 章把它们用在同一个现象上。

## 本篇贯穿的两条纪律

**一、能复现比好看重要。** 第 7 章会反复说明一件事：不可复现的 Baseline 比没有更糟，因为你会拿它去比较，得出的差异可能全部来自实验条件不同。随机种子、Warmup 排除、测量窗口、环境指纹，这些看起来琐碎的字段，决定了半年后这份数据还有没有用。

**二、证据不足就写不足。** 这条从 Part 1 延续下来。第 8 章的客户端与服务端时长差值不要叫“网络耗时”，第 9 章没标注采集条件的 profile 不能和 Baseline 直接比，第 10 章的报告必须写出排除项和残留不确定性。一份承认“这段还没查清”的报告，比一份把空白都圆上的报告可信。

## 学完本篇你应该能做到什么

- 为 Chat、RAG、Agent 各写出一份完整的 workload 描述，包含它们各自特有的字段；
- 说出手上这份压测是闭环还是开环，以及它测不出什么；
- 判断当前实验精度下，多大的差异才算真实变化；
- 从一条告警下钻到具体的慢请求 ID 列表；
- 说出一个现象该用哪一层的工具，以及上一层为什么不够；
- 把“服务慢”改写成含量值、范围、时间和对照的可调查问题；
- 为一个现象提出多个竞争假设，并按证据成本排序；
- 区分相关与因果，主动寻找反例；
- 产出一份含排除项和残留不确定性的根因报告。

## 进入下一篇之前的检查清单

- [ ] 手上有一份 workload 描述文件，含随机种子，重跑能得到同一批请求。
- [ ] 手上有一份 Baseline 报告，四块字段齐全，同事照着能重跑。
- [ ] 知道这份 Baseline 的波动是多少，以及它能识别多大的改善。
- [ ] 能用一个 Request ID 在客户端记录、服务端日志和引擎指标里都找到同一条请求。
- [ ] 指标标签里没有高基数字段。
- [ ] 每份 profile 都标注了采集条件、窗口和开销。
- [ ] 完成过一次完整的根因调查，报告里有排除项和残留不确定性。
- [ ] 验证改动时用的是同一份负载和同样的 Baseline 协议。
