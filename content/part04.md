# Part 4 Decode、KV Cache 与生成优化（Decode & Memory）

## 本篇导读

Part 3 把首个 token 之前的时间压了下去。但用户等待的大头往往不在那里。

一个 500 token 的回答，首包只占开头一小段，剩下的是一个一个吐出来的。这些间隔叠起来才是用户真正的等待时间，而它由一套完全不同的机制决定。

差别有多大？Prefill 一次处理几千个 token，权重读一遍被几千个 token 共用，瓶颈在算力；Decode 一次只处理一个 token，权重还是要完整读一遍，瓶颈在显存带宽。**同样的搬运，八千分之一的计算**（这里的八千是相对一次 8000 token 的 Prefill 而言）。这个反差决定了 Part 3 那四条路在这里几乎全不适用：缩短 prompt 对 TPOT 没用，Prefix Cache 管不着已经在生成的请求。

本篇还要结清第 12 章欠下的一笔账。那一章只算了上下文对 TTFT 和 token 账单的影响，没算显存。而显存决定了这张卡能同时服务多少人，这笔成本通常比前两笔加起来还贵。

## 本篇主线

```text
一个 TTFT 已经达标的服务（Part 3 的终点）
  -> 先搞清 Decode 的时间花在哪      Ch15
  -> 算清显存账，它决定并发上限      Ch16
  -> 用精度换容量和速度              Ch17
  -> 不动精度的另外两条路            Ch18
  -> 五个指标一起看，逐项验证        Ch19
```

第 15 章和第 16 章是一对：一个讲带宽怎么限制单步耗时，一个讲显存怎么限制并发数。它们给出两个可以直接算的下限，后面三章的所有手段都在推这两个数。

第 17 章和第 18 章是一组对照：前者动精度，换来的收益最大但有质量代价；后者不动精度，收益依赖负载特征。选哪条取决于第 15 章那个对照的结果。

## 本篇靠哪条道理

主线位置：优化与验证，第四步的后半加第五步，动的是首包之后那一段。和第 0 章的关系：本篇的搬运下限就是第 0 章第一条规律后半句与第二条规律前半句合起来的定量形式。“每写一个 token 都要把权重搬一遍”给出分子，“批量能摊薄搬运”给出唯一的摊薄办法，两句话除一下就是下面那条式子。第 15.3 节会把这层关系再点一次。

Part 3 的算术强度落在算力那一端，这一篇落在带宽那一端，共用一条道理：**每生成一个 token 都要把权重完整搬一遍，而批量是唯一能摊薄这次搬运的办法。** 本书称之为搬运下限。

式子就是单步耗时的下限，`权重字节数 ÷ 显存带宽`。它有两个推论，本篇的手段全长在这两条上：把分子做小，就是第 17 章的量化；把这一次搬运分给更多 token，就是批量，以及第 18 章用投机解码在一次搬运里多算几个位置。注意批量摊薄的是搬运而不是计算，所以它把算术强度往分界点的方向推，推过去之后收益就停了。

它在什么地方失效：三处。长上下文大批量时 KV Cache 的读取会超过权重，分子要重算（第 16 章）；批量把比值推过分界点之后瓶颈换成算力，再加批量只增加延迟（第 15 章）；实测远高于这个下限时，时间其实花在调度上，量化压不动那一部分（下面第一条纪律）。

## 本篇贯穿的三条纪律

**一、先判断瓶颈形态，再选手段。** 第 15 章给出的那个对照贯穿全篇：实测 TPOT 与带宽下限的比值。接近 1 说明带宽确实吃满了，该走量化或投机解码；大于 2 说明时间花在调度上，量化再多也压不动那部分。第 17 章那个白做两周的案例，就是跳过了这一步。

**二、任何 Decode 收益都必须标注批量。** 这一篇几乎所有手段的收益都随批量变化，有的还会在高批量下反向。离线单请求测出来的加速，搬到批量 48 的线上可能完全不成立。不说明批量的 Decode 数字是不完整的。

**三、质量是否决项，不是加权项。** 第 17 章和第 19 章都强调：动了精度就必须跑质量评测，底线必须在实验之前写死。五个指标里四个改善、质量越线，结论是失败。

## 学完本篇你应该能做到什么

- 用权重字节数和显存带宽算出这个模型的 TPOT 下限，并和实测对照判断瓶颈；
- 解释 GPU 利用率 95% 和 TPOT 偏高为什么可以同时成立；
- 说明批量在 Decode 阶段为什么近乎免费，以及 KV 显存、算力翻转、Attention 不摊薄三处边界；
- 算出一张容量表，从模型参数推到单卡并发上限，并说明每一步折扣是给什么留的；
- 解释显存还剩 8 GB 却接不进新请求的三种可能；
- 从 ITL 序列的孤立尖峰判断是否发生了抢占；
- 分开算权重量化与 KV 量化的收益，说明前者主要改善延迟、后者主要改善容量；
- 构造一份能测出长回答退化和格式遵循退化的评测集；
- 在真实请求样本上测出投机解码的接受率，并用收益比公式判断是否划算；
- 画出 Goodput 曲线，找出优于 TPS 峰值的那个批量档位；
- 产出一份五维齐全、每个数字都标注批量的 Decode 优化报告。
