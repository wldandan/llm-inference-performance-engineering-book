# 图 0-2 制作说明：读题搬一次，答题搬 N 次

- 来源段落：第 0 章“0.3 读题可以一起读，答题只能一个一个写”中“搬”的定义与读写对比两段。
- 核心问题：同样的权重，为什么写一个 token 比读一个 token 贵？
- 阅读顺序：先比较左右两栏从权重引出的箭头数量，再比较计算块的宽度，最后看底部两个标签和“累在算 / 累在搬”。
- 关键结论：读题累在算，答题累在搬：同样一个 token，写出来占用的机器时间远多于读进去。
- 边界：右栏按“历史不再重算”的真实做法画，每次只算新的一个 token；橙色标签中的 980 GB 是 0.98 GB × 1000 的纸面推算，对应单个请求、稠密模型；只讲搬运次数与计算量的比例，不画时间线，区别于图 2-5、图 2-6；不出现带宽、算力等硬件规格数字。
